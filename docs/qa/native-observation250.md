## Concrete source work

`PartyWebStore.update()` at `LocalPartyApp.swift:710` observes `model.objectWillChange` and independently queues `publish()` on the next main turn for every notification. Each publication first invokes `publishRooms()` (`:853/926`), before menu readiness, full-payload in-flight and full-payload equality guards. Rooms rebuilds own/nearby dictionaries, reads the room-name UserDefaults getter and enqueues arguments for both fixed WK recipients. JavaScript's existing signature guard runs after this bridge crossing. This establishes redundant source work; it does not establish its share of physical popup stalls.

Actual `ServerModel` methods supply bounded burst shapes. `refresh()` at `:157–164` conditionally assigns state, ready, connectionStatus, catalog and settings during startup/recovery, for at most five notifications from those statements. An ordinary changed-state poll can produce only one. `command()` at `:183` sets working/message in its synchronous start; its result at `:189–201` assigns state/message/working in one result continuation. The fixture uses these one/two/three/five shapes, including the original refresh conditionals, rather than an invented hundreds-of-notifications stress workload. Discovery, background diagnostics and representation updates can supply other turns; they remain uncached.

## Bounded hypothesis and recovery constraint

Ignored `.localparty-build/perf250/native-observation/candidate.diff` adds exactly two queue bits and replaces the observation closure. A single queued callback reads the latest model on the next main turn. It clears both bits before publication, so a recursively observed change can schedule the following turn. Explicit publication calls, full publication, Rooms scripts, loaded/readiness handling, navigation, model actions and ACK/epoch handlers remain byte-identical.

Simple one-bit coalescing is unsafe for the original recovery contract: several queued legacy publications while WebKit holds a payload set `publishAgain`, causing one later publication after an ACK or rejection. A coalescer that removes those callbacks also removes that request and changes immediate error retry/failure-budget behavior. This candidate captures one repeated-notification bit and sets the original `publishAgain` flag only if the original readiness/model/failure guards permit it and payload delivery remains in flight after publication. It introduces no new timer, document cache, transport acknowledgement, retry queue or hidden-view suppression.

The larger per-recipient Rooms memoization idea stays unimplemented. It requires independent document epochs, explicit positive acknowledgements, readiness before action guards, missing-module recovery and all load/navigation invalidation paths described in [native-display248.md](native-display248.md). A final Room snapshot or a call-count decrease cannot by itself approve that protocol.

Root identified that the first receiver fixture omitted an existing recovery path. Consequently the old omitted-fallback fixture cannot establish a persistent product delivery failure. Its prepared/compiled, unexecuted source and manifest are preserved as `*-pre-didFinish.*`; it is not an executed regression result.
