# Нагрузочный замер текущей версии — 9 октября 2026

[Выводы и порядок дальнейшей работы](findings.md) · [CSV со всеми играми](comparison.csv) · [Машиночитаемые результаты](comparison.json)

Исходники приложения не менялись. Запрошено по 20 игроков: проверены реальные попытки входа; в комнате допускается 16, у части игр игровой предел ниже. Нагрузочный замер выполнялся на фактически допустимом составе. Принудительного обхода лимитов не было.

Стенд: Apple M1 Max, 10 CPU, 64 ГБ RAM, Node v22.23.1, embedded worker, реальный Chromium ТВ 1280×720. Генератор команд — отдельный процесс. До 30 секунд на игру, прекращение при итогах матча. Проверено 36/36 игр.

Это loopback на Mac: без Wi-Fi, AirPlay, физического iPhone и native Rapier. WebSocket RTT — путь туда-обратно через gateway и игровой сервер, а не задержка «палец → пиксель». Интервалы снимков измерены отдельно; подтверждение команды — только где протокол его предоставляет. Нельзя выдавать частоту событийной викторины за FPS, а низкую частоту секретного пульта — за просадку.

CPU сервера включает launcher + worker; 100% = одно полностью занятое ядро. CPU ТВ — TaskDuration браузерной страницы, без полной стоимости GPU/композитора. RAM — p95 RSS серверного процесса. Диагностический preload добавляет измерительные накладные расходы; записи игровых циклов включают callback, а не только физику. Пульты отправляют непрерывное управление около 30 Hz там, где это соответствует протоколу; пошаговые действия — только согласно состоянию/роли. «Ввод» показывает число участников, реально отправлявших игровые команды внутри окна; ожидающие своего хода остаются подключены.

Поток — суммарный исходящий игровой payload всем пультам и одному ТВ, без HTTP-ресурсов, TLS и сетевых заголовков. Допущенные игроки / ввод могут различаться из-за очереди ходов, выбывания, раздачи ролей или отсутствия доступного действия. Нулевой/малый ввод требует отдельной оценки покрытия, а не заключения об отсутствии нагрузки.

Chaos пересылает ввод на ТВ, где считается игра: state/s=0 для него ожидаемо. Частота всех сообщений приведена в JSON отдельно. Для остальных событийных игр длинный интервал между состояниями может означать ожидание действия, а не сетевую задержку. Показатель rAF в сырых данных измеряет вызовы animation callback, не гарантирует столько же нарисованных/показанных кадров. RTT измеряется из процесса нагрузчика; его интервалы отправки также сохранены, чтобы выявлять собственные задержки стенда.

## Повторные сценарии

В сводке использованы уточнённые прогоны из `recheck/` и `naval-recheck/`: Naval соблюдает cooldown выстрела и распределяет цели по устойчивому кругу игроков, Punchmeter нажимает только в свой ход после подготовки, Crane прицеливается перед сбросом, Knives дополнительно фиксирует изменения счёта/оставшихся ножей. Первичные результаты сохранены отдельно. Это корректировка нагрузчика, исходники игры не менялись. Первый Naval с 544 отказами не используется как нормальный игровой сценарий; промежуточный повтор имел 44 отказа при конкурирующих выстрелах в одну клетку.
