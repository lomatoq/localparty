Исходный белый кадр подтверждён визуально. **Причина не установлена, постоянный продуктовый дефект не воспроизведён.** Production, общий CSS и галерея не изменялись. Нельзя объявлять это ни исправленным багом, ни доказанным артефактом capture.

Сохранены `.localparty-build/naval-final-audit/original-white.png` (точная копия исходного №277) и `stable-results.png` (пересъёмка устойчивого финала). `diagnostic.json` содержит DOM, фазы и геометрию свежего прогона. `before.png`, `after.png`, `accelerated.png` — дополнительные диагностические кадры, а не before/after изменения продукта.

Три изолированных WebKit-прогона с настоящим сервером, человеком с длинным именем и тремя ботами показали флот и заголовок победителя. Один прогон использовал QA clock12×, остальные нормальную скорость. На каждом путь завершения — разрешённый host finish, без подмены engine state. Ошибок JS на ТВ не зарегистрировано. Последний прогон проверяет одновременно API phase=results, TV HUD Results, iframe data-game-phase=finished и четыре карточки флота. Полноразмерная пересъёмка просмотрена: белой области нет, фон тёмный, все4 флота видны. Это ограниченная регрессионная проверка рендера, не проверка боя или всех путей завершения.

В коде `games/naval/server.js` finish вызывает broadcast и передаёт finished→results. `app.js` устанавливает gameScreenPhase, а `broadcast.js` сохраняет обзор флотов и показывает победителя. В `public/tv.js` src iframe меняется по instance, а не по results; специальной загрузки пустой страницы на финале не найдено. `screen-podium` в TV broadcast скрыт стилями, поэтому основной финальный контент здесь — обзор флотов и заголовок. Менять это без отдельного дизайна не стали.

Подтверждена слабость capture-предусловий: после API results iframe уже мог быть finished, а TV HUD ещё Battle. Ожидание фиксированных900–1800мс не гарантирует синхронизацию. В `tests/naval-final-browser.cjs` добавлено семантическое ожидание всех трёх поверхностей состояния. Это объясняет риск переходного снимка, но само по себе не объясняет исходную белую область; для точной причины нужен повторный сбой с trace/network/DOM того же момента. На новом снимке длинный заголовок победителей и свернутый счёт остаются UX-замечаниями.
