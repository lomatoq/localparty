## Activation, navigation and recovery audit

`sceneDidBecomeActive` skips the first reload but increments `externalDisplayReload` on every later activation until disconnect (`:37–49`). That published value enters `PartyTVContent.loadID` (`:108–127`); when SwiftUI observes a changed task identity, `renderer.load` cancels the retry task, sets loading status, immediately closes the native curtain and navigates the WKWebView (`:213–220`). No current navigation identity, `isLoading`, healthy document or socket catch-up condition is checked by activation. This can discard a healthy TV document on an ordinary reactivation, but no frequency/cost is inferred from absent149 cast logs. SwiftUI may coalesce rapid model changes, so the number of actual WK loads needs a runtime counter rather than multiplying callbacks from source.

Apple defines activation as becoming active, independently of scene connection/disconnection. It recommends preparing an existing scene and avoiding blocking activation work. Activation therefore does not itself prove that a full document reload is necessary. [Apple UISceneDelegate](https://developer.apple.com/documentation/uikit/uiscenedelegate), [Preparing your UI to run in the foreground](https://developer.apple.com/documentation/uikit/preparing-your-ui-to-run-in-the-foreground).

Current recovery paths are explicit main-frameHTTP≥400, non-cancelled navigation failure and WK content-process termination; each schedules a2-second retry (`:254–280`). The loaded callback only tests `url != nil`; it does not compare the callback's `WKNavigation` with a retained current navigation. A superseded callback could clear loading/retry state for a newer request, but that is a race hypothesis until reproduced with actual WK navigation objects. [Apple WKNavigationDelegate](https://developer.apple.com/documentation/webkit/wknavigationdelegate).

A healthy-reactivation change is not part of the cache candidate and must not simply delete recovery. Required separate proof: retain current navigation/document identity while healthy; activation during an in-flight load must not duplicate it; content-process termination/current-load failure must still reconnect; old navigation completion/failure must not settle or restart the new load; explicit screen refresh, boot/URL change and disconnect/reconnect must still create/load the correct destination. Then verify real socket/state catch-up and native curtain ownership around background/foreground and rapidly overlapping game transitions. Root must confirm the actual receiver topology first.

## Read-only Rooms bridge dedupe protocol

Root requested an independent audit of `LocalPartyApp.swift:854/922`. `publish()` invokes `publishRooms()` before menu readiness, full-payload in-flight and full-payload equality guards. The Rooms publisher rebuilds dictionaries and sends two separate WK `callAsyncJavaScript` requests with no completion handler, even for identical Rooms values or an unloaded/hidden controller. JS `nearby-rooms.js:145` compares serialized `[rooms,selected]` only after this native→WebKit crossing. Its stable-row patch preserves editing focus, but does not avoid native argument construction/copy and the repeated JS entry. This source path is concrete; no physical timing reduction is claimed by this read-only proposal.

Do not use a single global `lastRooms` or cache at send time. Menu and controller have independent documents; same-URL reloads create a new JS module with an empty signature, and a call before the module exists currently returns undefined. Safe delivery state is bounded to the two fixed WK recipients, with for each: current document epoch/readiness, last acknowledged typed snapshot, one in-flight snapshot and one replaceable latest desired snapshot. A snapshot is exactly the ordered Rooms rows (id/name/game/phase/players) plus selected id. Preserve row order and include the selected id even when that remote room disappears. Use native Equatable typed rows for early comparison; build bridge dictionaries only when a target actually needs a send. This removes redundant serialization/argument construction without relying on hash collision or transient URL alone.

A proposed send has an explicit acceptance boundary:

```js
const receiver = window.LocalPartyRooms;
if (!receiver || typeof receiver.update !== 'function') return false;
receiver.update(rooms, selected);
return true;
```

`update` currently returns undefined even on success, so optional-chaining completion alone cannot acknowledge delivery. Only native completion with explicit Boolean true, unchanged target document epoch and the captured sent snapshot advances that target’s acknowledged snapshot. Failure/missing module leaves the latest desired value pending. Do not acknowledge a payload just because dispatch succeeded. One in-flight request plus a single latest desired replacement coalesces A→B→C, sending C after A settles; if desired returns to acknowledged A, skip obsolete B. Preserve the last accepted current-document snapshot while an in-flight newer snapshot is rejected. No unbounded history or retry queue is needed.

Invalidate the target synchronously before every native menu/controller `load`, explicit refresh, URL switch/join, and content-process termination; also cover independently initiated allowed main-frame navigation. Native load sites include update/showController, reloadController/reloadMenu, joinRoom and content-process recovery. The existing full Host payload `deliveryEpoch` belongs to the menu and is not a sufficient controller-document identity. A same-URL reload must invalidate exactly like a new URL; old completions must be ignored rather than clearing a new in-flight slot. A valid current-document didFinish and Rooms module readiness force a per-view resync without invalidating the other view’s accepted state. Do not start an endless retry loop while an unloaded document lacks the module: keep one latest desired snapshot and flush at a valid readiness event/recovery attempt.

There is a specific prerequisite for this dedupe: current `receive()` first requires `shell || player`, where player requires `showingController`, then requires `phase == .active`, before handling `rooms-ready` at1104. Consequently a trusted main-frame controller readiness signal while hidden/inactive is discarded. Current repeated publishes may later mask this by resending. A safe implementation must recognize passive Rooms readiness for the two trusted current main frames independently of visibility/foreground, before the action guard; retain origin/view/current-document checks. This is transport readiness only: join, rename, sensors and other actions keep their existing foreground/user/authorization rules. Do not broaden admin capability or trust game child frames.

Retain the separate `renamed(name)` response unconditionally for successful unchanged-name saves and validation failures. Rooms signature dedupe must not swallow that action acknowledgement, which clears pending Save UI, displays validation/Saved state, collapses the editor and restores focus. `NearbyRooms.ownName` changes through UserDefaults and explicit publish rather than a model-only published property; compute the snapshot at those explicit calls. Selected remote host disappearance still retains the selected id and return-to-own behavior; reappearance, player/phase/game/name changes must send immediately. Hidden-view parking/coalescing is a separate change: the narrow first candidate should dedupe identical payloads while retaining current delivery semantics, rather than simultaneously dropping changed hidden state.

Required correctness/measurement gate before implementing/promoting: actual WK menu+controller with delayed module availability; repeated identical publish requests after explicit ACK; each own/remote name/player/phase/game/selected change; unchanged-name and invalid rename acknowledgement during typing; join/return and selected-host disappear/reappear; same-URL/new-URL reload while delivery is in flight; old callback after epoch change; lost/hidden/inactive rooms-ready; receiver exception/process termination/recovery; retained hidden view returning visible with latest state. Record native publication, typed snapshot build, bridge attempts/ACKs/coalesced requests and document epochs, plus JS actual update/DOM-mutation counts separately. Compare equal geometry, real focus/keyboard behavior and active state before interpreting a native call-count reduction as phone/cast performance. No additional native dedupe change is implemented by this lane.
