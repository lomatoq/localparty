## Round 3 · iOS Simulator (iPhone 17, real app build) and richer UI

Built with `npm run ios:prepare` + `xcodebuild` (Debug, simulator) and played on the app's own server (port 8081) with two background guests and the TV at 1280×720 in a browser.

Defects found on the device and fixed:
- **Controller overlap in the app** (user screenshot): inside the shell iframe, controllers added `env(safe-area-inset-*)` again; WKWebView reports the screen insets to the iframe, so the top had an empty ~60pt band and HOLD TO SWEEP overlapped the hint/SOUND row. Managed iframes now use fixed padding: `games/sports_siege/public/style.css`, plus a shared override for party, arcade_deluxe, bow_club, crane, millionaire, jenga, monster, tankarena, tanks in `public/game-ui-system.css`. Re-verified on iPhone 17 (curling and Bomb Tag).
- Search only matched brand titles ("bowl" found nothing): native hub (`public/tv.js`) and guest catalogue (`public/app.js`) now also match id, tag and description in both languages.
- Fresh rail ignored search: hidden cards forced visible by `display:…!important`; `[hidden]` now wins.
- "1 games" → correct plural; "1 points" → "1 point" in the sports controller.
- Running-game card label "OPEN CONTROLLER" was clipped → "PLAY".
- Search fields had no clear control → shared 44px × (`HeyPalsSearchClear`), attached on first input.

Richer UI (shared, `public/game-ui-system.{js,css}`):
- Stat glyphs: Game Icon Pack silhouettes by meaning (WINS crown, BOMB bomb, HEALTH heart, BEST lightning, LAP racing, TOTAL trophy…), tinted, bump once on value change; painted by CSS mask so labels rewritten every tick don't flicker.
- Procedural shields for places 4+ in standings (podium art stays top-3 only).
- Ready burst: procedural star/diamond/dot sprites from the Ready button when the server confirms ready.
- Your-turn cue: heading card springs with a sheen and a light haptic when it becomes this player's turn.

Tests: `npm test` 575/575; catalog-reveal, result-celebration, waiting-layout, tv-game-layout pass. `input-release-browser` passed 11/11 earlier this session but is flaky under the current machine load (simulator + app server): three reruns failed at three different points (bomb/tanks reconnect timing, a TV frame wait).
