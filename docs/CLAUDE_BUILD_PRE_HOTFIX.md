# LocalParty — задание Claude Code на Mac

Работай с `lomatoq/localparty`, ветка `codex/ios-unified-host-20260917`.
База до изменений: `ios` / `f54ac52224c319ac6249d6bfad76d329242cb6de`.
Нужен установленный рабочий iPhone-билд, а не ещё один план. Не публикуй приложение в App Store и не покупай подписки. Personal Team пользователя подходит для личной установки.

## Что уже изменено

`ios/LocalParty/LocalPartyApp.swift` теперь использует новый нативный shell на настоящих общих CSS-файлах веб-лаунчера. Кнопка «Ведущий» находится в меню рядом с «Пульт». Панель содержит AirPlay, Wi-Fi/QR, игроков, haptics, экран, статистику и диагностику. Стандартные SwiftUI Form/TabView заменены этим shell. Игровой пульт `/play` сохранён отдельным постоянным WKWebView. Внешний экран и сервер используют прежний ServerModel.

`public/native-shell/` содержит интерфейс и native-only адаптер haptics. Shell получает снимки состояния из Swift, не admin token. Только главный документ `partyapp://local/native-shell/index.html` внутри конкретного menu WKWebView может отправлять команды ведущего. У игрового WKWebView разрешены только возврат в меню и haptics, с проверкой реального protocol/host/port. Не ослабляй эти границы.

Добавлены строки системных разрешений, отмена удерживаемого ввода и отложенной вибрации при скрытии пульта, защита от инъекции HTML из имён игроков, сохранение фокуса при обновлении состояния, подтверждение опасных действий. Haptics — короткие UIKit impacts, не точное воспроизведение физических force-feedback waveform.

## 1. Защити рабочую копию

Прочитай `git status`, текущую ветку и HEAD. Сохрани незакоммиченные изменения и данные, ничего не сбрасывай. Используй новый `git worktree` или отдельный clone. Получи ветку из origin. Не подменяй её старой `master` или `ios`.

Проверь, не появились ли более свежие коммиты в ios/master с момента базы. Если появились, сравни историю и интегрируй актуальные изменения, не выбрасывая новую панель. Не force-push и не merge в защищённую/основную ветку без запроса пользователя.

## 2. Проверь актуальные версии, а не только номера из этой инструкции

На 17.09.2026 официальные источники показывали:
- Xcode 27 stable, iOS 27 SDK, Swift 6.4; нужен macOS Tahoe 26.6+. Xcode 27.2 beta НЕ выбирать.
- Node desktop LTS 24.21.0; Current 26.9.0 — другая ветка, не обязательная для сборки. `.nvmrc` содержит 24.21.0.
- Последний официальный nodejs-mobile iOS release всё ещё 18.20.4. Он встроен в приложение и НЕ заменяется установкой Node 24 на Mac.
- WABT 1.0.42 выпущен 15.09.2026. В текущем prepare-ios.py ещё закреплён 1.0.41.
- Three.js 0.186.0 совпадает с проверенным npm latest.
- Express latest 5.2.1, в проекте 4.22.2. Это миграция major, не безопасный blind update.

Источники: https://developer.apple.com/xcode/system-requirements ; https://nodejs.org/en/download ; https://api.github.com/repos/nodejs-mobile/nodejs-mobile/releases/latest ; https://api.github.com/repos/WebAssembly/wabt/releases/latest ; https://registry.npmjs.org/three/latest ; https://registry.npmjs.org/express/latest .

Запусти `node scripts/check-release-versions.cjs --strict`. Он опрашивает официальные источники и npm registry для ВСЕХ прямых зависимостей, devDependencies и overrides, пишет `.localparty-build/versions.json` и ничего сам не обновляет. Ошибка сети — «не проверено», не «всё актуально». Сопоставь каждую найденную версию с package-lock. Никаких beta/RC, `npm audit fix --force`, непроверенных форков или понижений версий.

Обнови совместимые стабильные зависимости, зафиксируй точные версии и lockfile. После каждой связанной группы прогоняй тесты. Для production dependencies дополнительно проверь совместимость с ВСТРОЕННЫМ Node 18.20.4, а не только настольным Node 24. Устаревший мобильный runtime отдельно отрази как риск для публичного релиза.

WABT 1.0.42: сначала сохрани рабочую связку 1.0.41, затем проверь release SHA256, обнови generator вместе с runtime headers/wasm-rt из того же релиза, пересоздай rapier2d/3d C, проверь PhysicsBridge и patch-native-widths, скомпилируй. Не смешивай новый wasm2c со старыми runtime headers. Для macOS arm64 опубликован asset digest `sha256:3f654779b436c628db3ca4323c51538815f5fbc887a6d5f3bb1c18d36281e240`; перепроверь перед использованием. При несовместимости не прячь ошибку: оставь последнюю рабочую закреплённую связку и укажи точный блокер в отчёте.

Express 5 требует проверки путей всех игр и `path-to-regexp` override. Не ставь Express 5 поверх глобального override 0.1.13. Переход выполняй как миграцию с интеграционными тестами всех игр; не ломай работающий билд ради большего номера.

## 3. Подготовь Mac

Проверь macOS, архитектуру, свободное место, Xcode, SDK, Node/npm и Python. Используй самый свежий стабильный Xcode, который официально поддерживает данный Mac и версию iOS телефона. Не обновляй macOS, не принимай соглашения и не вводи платёжные/учётные данные за пользователя. Если необходимо действие пользователя — попроси только конкретный клик/авторизацию, остальные шаги выполни сам.

Установи недостающие обычные инструменты существующим package manager. Существующая генерация физики требует Apple Silicon. Не переустанавливай рабочие инструменты без причины.

Запусти:

```bash
node --test tests/native-shell.test.cjs
bash scripts/build-ios-local.sh --simulator
```

Скрипт делает npm ci, тесты проекта, существующий ios:prepare, синхронизацию ресурсов и unsigned simulator build. Логи находятся в `.localparty-build/`, папка сама себя исключает из Git. По умолчанию сборка получает 0.11.0 (14). Приведи MARKETING_VERSION / CURRENT_PROJECT_VERSION в pbxproj к той же версии, чтобы ручной Run в Xcode давал согласованный результат.

Не обещай успешную компиляцию заранее: Swift/WebKit изменения ещё НЕ компилировались с iOS SDK в этой среде. Исправь реальные compiler/API/actor-isolation ошибки, не убирая origin checks, функциональность или общий дизайн. Не повышай минимальную iOS 17 только потому, что SDK новее.

## 4. Проверь новый shell в симуляторе

Запусти приложение. Проверь загрузку кастомной scheme, шрифтов, общих CSS, всех обложек, получение первого snapshot, readiness и восстановление WebKit после termination. Старый SwiftUI Form не должен появляться. Отсутствие/ошибка ресурса не должны оставлять чёрный экран.

Сними реальные скриншоты главного меню, открытой панели ведущего и настроек игры. Сравни с реальным веб-лаунчером: кнопки `.nav/.quiet/.lime/.primary`, панели `.company`, `.player/.rank-row`, типографика и отступы должны быть общей системы. Не создавай новую тему, не заменяй игровую графику, не перерисовывай сами игры. Проверь узкий экран, safe area, скролл модалок, Dynamic Type/увеличение текста, reduced motion, возврат фокуса.

Проверь последовательность: открыть меню → подключить экран → включить Wi-Fi → войти своим пультом → вернуться в меню без потери профиля → выбрать игру и её настройки → Я готов у каждого → матч → пауза/продолжение → смена раунда/повтор → лобби. Настройки отправляются через существующие ServerModel.command / host-controls, не через дублированную систему.

Проверь, что JavaScript игрового iframe НЕ может выполнить manage/network-set через bridge, даже послав правильный type; guest Safari и LAN не получают ключ ведущего. Поддельные/чужие origins отклоняются. Не добавляй общедоступный `/admin` или незащищённый `/host`.

## 5. Собери на физический iPhone

Найди подключённое/сопряжённое устройство через `xcrun devicectl list devices` и свой Apple Account/Personal Team в Xcode. Не используй записанную в старом проекте чужую Team. Подбери уникальный Bundle ID. Разрешения Trust/Developer Mode/Apple Account пользователь подтверждает сам при необходимости.

```bash
bash scripts/build-ios-local.sh --device "$DEVICE_UDID" --team "$TEAM_ID" --bundle com.hleb.localparty.personal
```

Скрипт собирает, подписывает под указанной командой, устанавливает через devicectl и запускает. Не удаляй существующее приложение/профили ради установки: изменение Bundle ID создаёт отдельное приложение с отдельными данными. Personal Team требует обновления подписи примерно раз в 7 дней; покупка Developer Program не нужна для этого личного сценария.

Проверь физически: отдельная сцена AirPlay, встроенный пульт на том же телефоне, игра с телефонами гостей, настоящий отклик Taptic Engine по игровому событию, отмена вибрации при уходе, отказ/повтор запроса motion permission, поступление реальных sensor samples в Punch Meter. UIKit паттерны могут ощущаться не так, как Android vibration; настрой интенсивность по реальному устройству. Не называй симулятор доказательством работы вибрации, акселерометра или задержки AirPlay.

## 6. Важные оставшиеся ограничения

Гостевой порт iPhone-хоста в `lib/network-access.js` пока HTTP. Новый UI честно это показывает. Эта ветка не выдаёт простой HTTPS label за реализованный доверенный TLS. Для завершения гостевого motion-сценария нужна отдельная доработка HTTPS: отдельный TLS listener для гостей, HTTP loopback для WKWebView и ServerModel оставить, корректные HTTPS/WSS URL и проверки Origin по реальному listener, сертификат на адрес из QR, безопасный импорт и доверие на каждом гостевом iPhone. Не отключай проверку сертификатов и не публикуй закрытые ключи/CA/Personal Team provisioning в Git. Для первого билда HTTP button/joystick fallback обязан оставаться рабочим.

Полная вибрация Safari гостей не добавляется установкой нативного приложения только у ведущего. Нужен нативный пульт на соответствующем iPhone либо честный fallback. Не выдавай checkbox-haptic hack за надёжную отдачу от удалённых столкновений.

Фон и AirPlay не гарантированы при блокировке: сохрани существующие lifecycle/паузы и не используй фиктивное аудио или бесконечные задачи для обхода iOS.
