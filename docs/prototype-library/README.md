# Библиотека прототипирования LocalParty

Это первый источник ассетов и проверенных систем для новой альфа-игры. Если пользователь не дал специальные ресурсы, сначала выбираем подходящие элементы из [`catalog.json`](./catalog.json). Новую графику генерируем или скачиваем только тогда, когда библиотека не закрывает задачу либо не проходит визуальную проверку сцены.

Полный машинный индекс всех файлов `public/assets/**` и всех реализаций `games/*/**` хранится в [`inventory.json`](./inventory.json). Он включает не только новые игры: для каждой игры перечислены сервер, рендер, контроллер, стили, тесты, данные и локальные ассеты. `catalog.json` поверх него отмечает уже понятные и особенно полезные коллекции и системы.

## Быстрый старт

1. До выбора ассетов зафиксировать режим сцены: `2d-top-down`, `2d-front`, `pseudo-3d` или `3d`.
2. Найти коллекции командой `node scripts/check-prototype-library.cjs --find <слово>` либо через `findAssets()` из `lib/prototype-library.cjs`.
3. Брать сначала элементы со статусом `alpha-approved`. `visual-gate-required` можно брать в альфу после проверки в реальной сцене. `preview-or-visual-gate` нельзя считать готовым игровым спрайтом.
4. Подключать существующий файл по его пути. Каталог не копирует изображения и не создаёт ещё один тяжёлый бандл.
5. Пройти визуальный gate ниже на ведущем экране и мобильный gate на контроллере.

```js
const library = require('../../lib/prototype-library.cjs');

const candidates = library.findAssets({
  category: 'effects',
  projection: '2d-top-down',
  status: ['alpha-approved', 'visual-gate-required']
});
```

## Главное правило камеры

Спрайты одной игровой плоскости должны быть сняты одной камерой. Для top-down сцены башня, основание, враг, снаряд и эффект смерти должны быть строго сверху. Боковой или трёхчетвертной рендер башни нельзя «довернуть» в рантайме: перспектива и видимые боковые грани останутся неверными.

Для `2d-front` цели и препятствия смотрят строго в камеру и имеют общую линию пола. В `pseudo-3d` заранее фиксируются азимут, высота камеры и проекция. В `3d` используются модели и свет сцены, а 2D-спрайты допускаются только как явно экранные эффекты или UI.

Стены и тайлы проверяются собранной полосой, а не по одному кадру. Соседние элементы должны стоять ровно, иметь одинаковый масштаб, общую базовую линию и стыковаться без дыр, наложений и скачка перспективы.

## Визуальный gate

Ассет или система готовы к альфе, только если выполнены все пункты:

- камера и проекция совпадают с режимом сцены;
- размер объекта логичен рядом с персонажем, препятствием и целью;
- pivot соответствует физическому смыслу: стопа стоит на земле, турель вращается вокруг основания, снаряд выходит из дула;
- анимационные кадры сохраняют pivot, масштаб и силуэт;
- вокруг объекта есть безопасное прозрачное поле после trim и упаковки;
- в атласе нет пикселей соседнего кадра и texture bleeding при масштабировании;
- повторяемые стены и тайлы проверены цепочкой минимум из пяти элементов;
- выстрел читается как «дуло → снаряд → прикреплённый трейл → попадание → затухание», без старой отдельной линии;
- смерть читается до удаления сущности; для отличающихся классов нужен свой sheet или явно подходящая процедурная смерть;
- декор поддерживает игровую зону и не выглядит случайным;
- при `prefers-reduced-motion` смысл обратной связи сохраняется.

Для сгенерированных атласов фон источника должен быть ровным `#ff00a8`: без градиента, текстуры, тени и свечения на фоне. В JSON-спецификации генерации обязательны камера, проекция, сетка, порядок кадров, pivot, safe margin и отрицательный промпт.

## Эталон минимального качества

`push` / Push Pit — эталон для быстрой альфы: простое поле, контрастные шайбы, ясная граница опасности, минимум декора и эффект только там, где он объясняет удар или вылет. См. `push-pit-reference` в каталоге. Новая игра может быть простой, но игровая плоскость, силуэты, движение и обратная связь должны выглядеть согласованно.

Это означает:

- один главный фокус на экране;
- свободное место вокруг игровой зоны;
- цвет игрока используется последовательно;
- UI сообщает только состояние, нужное прямо сейчас;
- эффект усиливает событие и заканчивается, не оставляя визуальный мусор;
- физика и графика используют один и тот же центр/контактную точку.

## UI и мобильный барьер

Для текста используется Rubik из `public/assets/fonts`. Для нового UI сначала переиспользуются `responsive-session-shell`, `shared-session-bridge` и `shared-game-clock`.

Для движения сначала подключаются `/motion.css` и `/motion.js`. Базовый набор состоит из `--motion-fast` для нажатия, `--motion-base` для смены значения или статуса, `--motion-slow` для входа панели и `--motion-stagger` для короткой очереди карточек. Верхний HUD въезжает первым, затем игровая поверхность и нижняя рейка; диалог получает один pop-in, а результат — спокойный glow и вращающиеся лучи из общего shell. Новая игра не добавляет собственную постоянную тряску или бесконечный декоративный цикл. `prefers-reduced-motion` полностью отключает переходы, сохраняя итоговое состояние и цветовую обратную связь.

Motion runtime наблюдает только presentation-состояние DOM. Он не отправляет websocket-сообщения, не меняет hitboxes, pointer/touch handlers или геометрию контроллера. Для альфа-прототипа достаточно подключить общую систему и пометить нестандартные значения `data-motion-value`, а фазы `data-motion-status`.

Телефонный контроллер не должен импортировать фон ведущего экрана, 3D-модели или полный игровой атлас. Его обязательные условия: `100dvh`, safe areas, портрет и альбом, hit target минимум 44×44 px, отсутствие перекрытия handedness-зон, джойстика, свайпа, огня, паса и sweep. Изменения управления проходят проверку поворота и переподключения.

## Статусы каталога

- `alpha-approved` — можно брать первым для альфы в совместимую проекцию.
- `quality-reference` — образец поведения или визуальной простоты; копировать принцип, а не обязательно код целиком.
- `reference-implementation` — рабочая реализация, которую надо извлекать с её зависимостями и тестами.
- `visual-gate-required` — путь и метаданные известны, но каждое применение проверяется в собранной сцене.
- `preview-or-visual-gate` — фон или промо-арт; не использовать как игровой спрайт автоматически.

## Поддержка каталога

После добавления ассета:

1. Добавить его в исходный manifest и затем в одну коллекцию `catalog.json`.
2. Указать происхождение/лицензию, проекцию, pivot, tint, кадры анимации, применение и ограничение мобильного бандла.
3. Добавить ссылку на production prompt или источник лицензии.
4. Запустить `node scripts/check-prototype-library.cjs` и `node --test tests/prototype-library.test.js`.
5. Только после визуальной проверки поднять статус до `alpha-approved`.

Если в `games/*` или `public/assets` добавился файл, сначала обновить полный индекс: `node scripts/build-prototype-library-inventory.cjs`. Проверка `--check` падает, когда индекс отстал от дерева проекта.
