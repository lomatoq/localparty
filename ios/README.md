# Local Party на iPhone

Этот проект встраивает весь каталог из основного репозитория: 26 игр работают на iPhone. Компьютер нужен для установки через Xcode. Телевизор подключается через AirPlay или браузер, телефоны гостей — через браузер в одной сети Wi-Fi.

## Запуск

На этом Mac проект уже подготовлен: откройте `ios/LocalParty.xcodeproj`, выберите схему **LocalParty**, свой iPhone и нажмите **Run**. Настроена автоматическая подпись Team `KKM3M9K749`; новый bundle ID — `com.localparty.launcher`. Предыдущий прототип с танками не перезаписывается.

1. В приложении откройте **Комната → Запустить сервер**. Разрешите доступ к локальной сети.
2. Выведите игру на ТВ через AirPlay: откройте Пункт управления iPhone → **Повтор экрана**, выберите телевизор и вернитесь в Party 26. Либо в браузере телевизора введите адрес из раздела **Комната → Игра на телевизоре → Или через браузер телевизора**, например `http://192.168.8.176:8080/tv`.
3. Гости сканируют QR на ТВ. Ведущий может открыть вкладку **Пульт** и войти как обычный игрок. Браузер остаётся альтернативой.
4. Выберите игру во вкладке **Игры**. Режим и параметры выбираются здесь же, на iPhone; обложка, правила и настройки сразу появляются на ТВ. Нажмите **Играть вместе**; после подключения контроллеров каждый нажимает **Я готов** на своём пульте.
5. Игра начинается автоматически после готовности всех игроков. Телевизор — только дисплей. Пауза, следующий вопрос/ход, повторная игра и возврат в лобби доступны в приложении; действия показываются только в подходящей фазе.

Адрес определяется по Wi-Fi-интерфейсу. При занятом 8080 приложение покажет фактически выделенный порт. Не используйте `localhost` или `127.0.0.1` на гостевом телефоне: это адрес самого гостевого телефона.

## Отдельный игровой экран через AirPlay

Телевизор с AirPlay или Apple TV показывает общий экран игры, а iPhone — каталог, комнату или встроенный **Пульт**. Браузер на телевизоре не нужен. Подключите устройства к одной сети Wi-Fi, запустите сервер, выберите ТВ через системный пункт **Повтор экрана** и вернитесь в приложение. Несмотря на название системного пункта, Party 26 выводит собственное отдельное окно, а не копию интерфейса телефона.

Нужен элемент **Повтор экрана** со значком двух перекрывающихся прямоугольников. Выбор телевизора через AirPlay в музыкальном плеере подключает только звук. Если элемента нет, откройте **Пункт управления → + → Добавить элемент управления**, найдите **Повтор экрана** и добавьте его.

В разделе **Комната → Игра на телевизоре** видны подключение внешнего экрана и число зарегистрированных общих экранов. Кнопка **Обновить картинку на ТВ** перезагружает только внешний экран. Чтобы отключить AirPlay, используйте **Пункт управления → Повтор экрана → Остановить повтор**. Подключение внешнего дисплея кабелем использует тот же механизм.

Держите Party 26 открытым: во время вывода приложение отключает автоматическое гашение экрана, даже если общий переключатель «Не гасить экран приложения» выключен. Ручная блокировка или переход в другое приложение могут прервать картинку; разрешение на фоновую работу сервера не гарантирует фоновый вывод AirPlay. Задержка и звук требуют проверки на физическом iPhone и конкретном приёмнике. Для быстрых игр стоит сравнить AirPlay с проводным подключением.

Реализация: `ExternalDisplay.swift` создаёт `UIWindow` для `windowExternalDisplayNonInteractive`. Отдельный встроенный `WKWebView` открывает тот же `/tv` через loopback и фактический порт сервера. Игры не переписываются; сервер, физика и пульт остаются на iPhone. Обе сцены используют один `ServerModel`. При отключении освобождаются окно и игровые соединения; ошибки загрузки и завершение процесса WebKit запускают повторную загрузку. Браузерный способ подключения сохраняется.

## Подготовка на другом Mac

Нужны Apple Silicon Mac, Xcode с iOS 26 SDK для фоновой задачи, Python 3 и Node.js/npm для подготовки ресурсов. Минимальная версия приложения — iOS 17; фон — iOS 26+.

```sh
npm ci
npm run ios:prepare
open ios/LocalParty.xcodeproj
```

Подготовка загружает **nodejs-mobile 18.20.4** и **WABT 1.0.41**, проверяет закреплённые SHA-256, создаёт нативные исходники физики и копирует все игровые ресурсы. При каждой последующей сборке Xcode синхронизирует текущие `server.js`, `games`, `public`, `lib` и зависимости. После обновления зависимостей сначала выполните `npm ci`. Обновление версии Rapier требует регенерации и проверки его нативных привязок, а не только замены npm-пакета.

`Vendor`, `.cache`, сгенерированные C-модули, содержимое `LocalParty/Server` и сборки не добавляются в Git. Файлы проекта, адаптер, нативные привязки и инструкции входят в репозиторий.

## Архитектура

- SwiftUI: три вкладки **Игры / Комната / Пульт**, каталог, список игроков, адрес ТВ и QR. Встроенный WKWebView открывает общий /play. Игрок создаётся только при входе в пульт; используется обычный порядок обработки команд. При уходе из пульта нажатия отпускаются.
- Один встроенный Node.js работает на отдельном потоке. Каждая запущенная игра получает `worker_threads`-изолят вместо запрещённого на iOS дочернего процесса. Desktop-запуск через `npm start` сохранён.
- HTTP и WebSocket доступны через один публичный порт. Игровые серверы слушают только loopback. Управление приложением защищено случайным ключом и доступно только с loopback; `/tv` получает отдельные права общего экрана и не может запускать игры через управляющий API.
- Rapier 0.20.0 для **Дженги** и **Крана** скомпилирован из исходного WASM в C заранее. Те же JavaScript-привязки вызывают нативные функции, включая контактную физику и восстановление памяти. На телефоне нет JIT, исполнения WASM или передачи расчётов телевизору.
- Профили и результаты хранятся в Application Support с доступом после первого разблокирования. Переподключение сохраняет идентичность; поздние команды от предыдущего экземпляра игры отклоняются.
- TCP работает без задержки малых пакетов. Медленному экрану не накапливают очередь старых кадров. QR и статические файлы лаунчера кэшируются; повторный вход с неизменным профилем не блокирует сервер записью на диск.

## Фон и ограничения проверки

Фон запрашивается автоматически при нажатии «Запустить сервер», до ожидания сетевого ответа. Сервер не имеет таймера завершения. `BGContinuedProcessingTask` получает прогресс из атомарного счётчика обслуженных циклов Node.js через отдельную очередь, независимо от SwiftUI и HTTP-опроса. Прогресс считает циклы Node с фиксированной верхней границей. Каждая попытка имеет отдельный идентификатор, завершение защищено от повторного вызова. Эти изменения ещё не подтверждены на физическом iPhone как решение ошибки Dynamic Island. При остановке приложения сервером или отмене задачи освобождается активный системный ресурс с `setTaskCompleted(success: true)`; программная очистка больше не объявляется сбоем. Если iOS отзывает фон, игровой процесс ставится на паузу до возвращения приложения. Системная пауза снимается автоматически; ручная пауза игрока сохраняется. Симулятор не выдаёт разрешение на длительный фон.

Это не бессрочный системный сервер: iOS может прервать задачу, приложение нельзя принудительно закрывать свайпом. Продолжение после системной паузы требует открытия приложения. На iPhone с iOS ниже 26 нужно держать приложение открытым. После смены сети откройте новый адрес с экрана «Комната».

Контроллеры доступны по HTTP. Датчик движения в **Punchmeter** может требовать HTTPS в браузере; кнопочное управление сохраняется. Поддержка WebGL зависит от браузера телевизора.

Проверки выполняются в установленном приложении симулятора и браузере общего экрана. Проверка реального фонового разрешения, его системной карточки и длительной игры при блокировке физического iPhone не выполнялась. Уже созданные iOS карточки со сбоем не удаляются через API отмены ожидающих задач. Подробнее: [Apple DTS о длительных сессиях](https://developer.apple.com/forums/thread/840384), [Apple DTS о карточках задач](https://developer.apple.com/forums/thread/808756).

## Проверки

[Результаты прогона и границы проверки](VALIDATION.md).

```sh
npm test
npm run test:session
npm audit
```

Для проверки встроенного сервера в симуляторе задайте тестовый ключ только процессу симулятора:

```sh
SIMCTL_CHILD_PARTY_TEST_KEY=localparty-integration-test xcrun simctl launch --terminate-running-process booted com.localparty.launcher
npm run test:iphone
# Для прямого запуска всех игр держите /tv открытым в браузере:
node tests/iphone-controls.cjs
```

Этот ключ включается только в simulator-сборке; на физическом iPhone всегда создаётся случайный. Если порт отличается, задайте `PARTY_TEST_ORIGIN=http://127.0.0.1:ПОРТ`. Проверка создаёт тестовых игроков и последовательно запускает игры, поэтому запускайте её в отдельной тестовой сессии. Можно ограничить список: `PARTY_TEST_GAMES=jenga,crane npm run test:iphone`.

Прогон проверяет весь каталог, отдачу страниц и мостов, синхронизацию выбора с ТВ, границы доступа, сохранение игрока при замене соединения, остановку и повторный запуск сервера. Для обеих игр с физикой он также подключает контроллеры, начинает игру, подаёт управление и измеряет поступление кадров. Эти проверки не заменяют прохождение всех раундов во всех браузерах.

- [Apple: Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars) и [Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars): постоянные разделы отделены от действий запуска и паузы.

## Надёжность сборки

Каждая сборка Xcode синхронизирует каталог, игровые файлы и сервер прямо в готовый `.app` и сверяет SHA-256 каждого ресурса. Копирование папки стандартной фазой ресурсов удалено: оно могло пропускать изменения вложенных файлов и доставлять на телефон старую серверную часть при новой оболочке.

## Комната, игроки и восстановление (0.8)

В разделе «Комната» у каждого игрока есть кнопка удаления с подтверждением. Она отключает его контроллер; остальные продолжают игру. На телефонах гостей — весь каталог в том же порядке, что у ведущего, поиск и три категории. На карточке можно отдать или снять голос; выбор другой игры переносит голос. После голосов всех подключённых людей сервер запускает лидера, при ничьей — случайного лидера. Автозапуск ждёт ТВ и загрузку контроллеров. Ведущий также может запускать игры вручную.

После прерывания процесса приложение автоматически поднимает сохранённую комнату, показывает событие прерывания и принимает прежние профили. Текущий раунд после завершения процесса нужно начать заново. Явная кнопка «Остановить сервер» отключает автоматическое восстановление комнаты. «Поделиться журналом сервера» помогает разобрать повторные сбои.

Дополнительные проверки (создают тестовых участников, запускайте в тестовой комнате):

```sh
node tests/iphone-load.cjs
node tests/iphone-restart.cjs
PARTY_TEST_LIFECYCLE_CYCLES=2 node tests/iphone-lifecycle.cjs
```

Последняя проверка требует действий Home/Lock в симуляторе при сообщениях WAIT. Не заменяйте её искусственным разрешением фонового исполнения.
